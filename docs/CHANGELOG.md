### v1.2.3 (2026-11-03)

**セキュリティ**

共有フォルダやTeams経由で受け取ったデータ（Markdown本文・コメント・同期パッケージ・プロジェクトJSON）に悪意のある内容が含まれていても、ブラウザ上でスクリプトが実行されないようにした。

- Markdownの表示結果をサニタイズするようにした（コメント・タスク詳細・Wiki・テンプレートが対象）。これまでは、Markdownに書かれた生のHTML（`<img onerror=…>` など）や `javascript:` リンクがそのまま実行された。許可するのは見出し・表・リスト・コード・リンク・画像・`<details>` など一般的なタグだけで、`<script>`・`<iframe>`・`<svg>`・`<form>`、`on…` 属性、`id`・`name`・`data-*` 属性は取り除く。リンクと画像のURLは `http(s)` `mailto` `tel` `file` `ftp` `msteams` `tfz` `wiki` と、画像の `data:image/…` だけを許可する。`class` 属性はコードのシンタックスハイライト用（`hljs-*`・`language-*`）以外を取り除く。`style` 属性は、`position: fixed`・`url()` などを含むものだけ取り除く。
- 添付リンク（`tfz://`）と Wiki リンク（`wiki://`）を HTML に変換するとき、リンク先の文字列に含まれる `"` や `\` で属性を突き破れないようにした。コードブロックの言語名（```言語名）も同様に無害化した。
- 画面の `onclick` などに埋め込むID・日付・プラグイン名・ラベル名・マイルストーン・メンション候補を、JavaScript の文字列として安全な形にエスケープするようにした（約50か所）。ラベル名などは、バックスラッシュとシングルクォートの組み合わせ（`\'`）で文字列を抜けられる書き方になっていたため、同じ処理に統一した。
- プロジェクトJSONを読み込む・取り込むときに、IDに危険な文字が含まれていないか確認するようにした。引用符（`'` `"`）・`<` `>`・`\`・制御文字を含むIDだけを、別の安全なIDに置き換える（空白・日本語・`&` などは問題ない）（IDを持つフィールドの値だけを対象とし、`milestoneId` などの参照も同じ値に揃える）。「いいね」「ブックマーク」「メンション既読」は `id` に自分の名前が入るため対象外で、名前・本文・投稿者などの文字列は一切書き換えない。`__proto__`・`constructor`・`prototype` というキーは取り除く。番号は、数字以外の文字列が入っていた場合だけ数値に直す。通常のデータは変更されない。不正なものを見つけたときは、1回だけ通知を出す。
- マイタスクのアクティビティに表示するチェックリストの文言、フォルダ履歴のフォルダ名、アバター画像（`avatars.json`）の扱いを、エスケープ・形式確認するようにした。
- 外部ライブラリ（marked・Chart.js・highlight.js）を、バージョンを固定し、SRI（ハッシュによる改ざん検知）付きで読み込むようにした。ハッシュが一致しない場合は実行せず、marked・Chart.js はこれまでどおり同じフォルダのローカルファイル（`marked.min.js`・`chart.min.js`）に切り替わる。highlight.js はハッシュが一致しなければ使わず、自作ハイライターのままになる。
- CSP（Content-Security-Policy）を `<meta>` で設定した。外部への通信はCDN（jsdelivr）だけを許可し、`<form>` の送信・`<iframe>`・`<object>`・`<base>` を禁止する。XSS対策の代わりにはならないが、万一スクリプトが実行されても、データを外部へ送りにくくなる。

**変更点**

- Markdownに直接書いた生のHTMLは、通常の使い方（`<br>` `<u>` `<mark>` `<kbd>` `<sup>` `<sub>` `<font color>` `<center>` `align` 属性、`<table>` とその `border` などの装飾属性、`<details>`、`<img width>`、`color` などの `style`）は従来どおり表示される。次のものは表示されなくなる: `<iframe>` `<video>` `<audio>` `<form>` `<svg>` などの埋め込み・フォーム系のタグ、`id` 属性（`<a id="x">` と `[…](#x)` によるページ内アンカー）、コードのシンタックスハイライト用以外の `class` 属性、`target` 属性（外部リンクは従来どおり新しいタブで開く）。HTMLコメント（`<!-- -->`）も取り除かれるが、表示には影響しない。
- 外部URLの画像は `https` のものだけ表示する（`http` の画像は表示しない。社内サーバーの画像などは添付ファイルにするか、CSPの `img-src` に追加する）。
- プラグインから外部のAPIなどへ通信する場合は、`taskflowzero.html` の CSP（`connect-src`）にそのオリジンを追加する必要がある。同梱のプラグインは外部通信をしないので影響はない。

**改善**

- 英語化プラグイン（`plugin/plugin_lang.js`）に、不正なIDを無効化したときの通知の訳語を追加した（プラグインバージョン1.3.14→1.3.15）。

- PC とスマホのデータは「同期パッケージ」（JSON ファイル）でやり取りする。Teams などでファイルを送り合う前提で、フォルダの共有は不要。

  - スマホ → PC：スマホでは「変更を書き出し」で、取り込んだ時点からの自分の変更分だけを書き出す（差分パッケージ）。ステータスなどタスクの項目の変更、チェックリストの操作、コメントの追加、新規タスク、アクティビティが対象で、全体を送るより小さく済む。共有シートに対応した端末では、そのまま Teams やファイルアプリへ送れる。PC では「スマホの変更を取り込み」で開く。
  - PC 側の取り込みは、既存の 3-way マージをそのまま使う。スマホの変更前の値と PC の現在の値が同じなら自動で反映し、食い違う項目だけ、これまでと同じ競合ダイアログで選べる（「保留」にもできる）。同じパッケージを 2 回取り込んでも、タスクやコメントは重複しない。

  - PC に取り込んだプロジェクトについて、スマホから PC へ反映されるのは、上に挙げた「軽い更新」だけ。タスクやプロジェクトの削除、プロジェクト・マイルストーン・Wiki の編集は反映されない（編集ボタンは出さない）。
  - PC をまだ使い始めていない場合は、スマホだけで始められる。取り込み画面の「新規で始める」を押すと、名前を入力して空の状態で始まり、スマホで「新規プロジェクト」を作れる。スマホで作ったプロジェクトに限り、プロジェクト情報・マイルストーン・Wiki もスマホで編集できる（その分、削除はできない）。

  - スマホに取り込み直すとき、まだ書き出していない変更（または書き出したが PC に取り込んだか分からない変更）があれば、失われることを確認してから進める。書き出していない変更が 3 日以上たまっていると、起動時にお知らせする。

- マージの対象外だった項目の変更が破棄されていた問題を修正した。プロジェクト・マイルストーン・タスクの固定項目以外のフィールド（プラグインが追加する項目など）と、Wikiページの並び順（order）を、他の項目と同様に3-wayでマージする。Wikiページの並べ替えが保存のたびに元へ戻っていたのはこのためである。

* タスクのチェックリスト追加欄（新規作成モーダル・タスクパネル編集の両方）で、改行を含むテキストをペーストした場合、1行につき1件のチェックリスト項目として追加されるように変更。改行を含まない通常のペーストは従来通りの挙動。
* `#P{プロジェクト番号}-{タスク番号}-C{コメント番号}`形式の参照リンクに対応。Markdown本文・コメント・Wiki内でこの形式のテキストを記述すると、該当タスクの該当コメントへ直接ジャンプするリンクになります（対象コメントが存在しない場合はリンク無効化＋取り消し線で表示）。

### v1.1.3 (2026-07-22)

**変更**
* プラグイン関連の設定（有効/無効・個別設定）を、プロジェクトフォルダ直下の `settings.json` から plugin フォルダ直下の新規ファイル `plugin-settings.json` に分離。プロジェクトフォルダ側に出力される `settings.json` はプラグインの設定値を持たなくなりました。
* 旧バージョンで `settings.json` にプラグイン設定が残っている場合、次回起動時（plugin フォルダへのアクセスが可能になったタイミング）に自動で `plugin-settings.json` へ移行し、`settings.json` 側からは削除されます。plugin フォルダ側に既に設定が存在する場合はそちらを優先し、上書きしません。
* `TaskFlow.registerPlugin()` / `TaskFlow.getPluginConfig()` など、プラグイン開発者向けAPIの呼び出し方法・戻り値に変更はありません。

### v1.1.2 (2026-07-10)

**バグ修正**
* タスクのコメントで見積時間を入力すると、タスク作成時に設定した見積時間が上書きされて消えてしまう不具合を修正。作成時の値を基準値として保持し、コメントでの入力はその基準値に対する加算として扱うように変更。
* 上記の修正に伴い、コメントの見積入力欄でマイナス値を入力できるように変更（見積を減らす調整が可能に）。実績入力欄は従来通りマイナス値を受け付けない。
* プラグインAPI（`TaskFlow.api.createTask` / `updateTask`）経由でタスクを作成・更新する場合も、同様の不具合が起きないように対応。

**機能追加**
* マイタスクのアクティビティタブで、指定した日付のアクティビティにタイムスタンプ（時刻）を表示するように変更。
* アクティビティの表示順を、時刻情報があるものは実際の時刻順、日付のみのものはその日の先頭にまとめる順序に変更。「その日、何時に何をしていたか」を振り返りやすくなりました。
